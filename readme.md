# 秒传Pro

`123 云盘` · 秒传 / 转存 / 离线下载 本机面板

**v1.5.17** · Windows x64 · 单文件 exe · Docker（amd64 / arm64）

中文 · 面板自带运行环境，这台机器不需要装任何东西

</div>

---

秒传Pro 是一个跑在**你自己机器上**的控制面板，把 123 云盘那套 JSON 秒传流程、分享转存和云端「链接任务」收进一个界面里：
清单进、清单出、分享存、离线下载，全部在一台本机面板里排队执行，进度与台账逐条落在本地磁盘上，断了能续跑。

## 核心能力

### 千万级分享转存

- 一条分享链接就能建任务，**递归下钻**整棵目录树、逐批转存，超大规模（千万级、含"超百万"被拒后自动降级逐批）不中止。
- **失败台账 + 重试**：记下落没落全的目录，支持本任务内重试，也能自底向上"点名"只补失败那几条路径。
- **逐层校验对账**：每层落盘后回读数量与总容量比对，明确告诉你"这层齐了 / 还欠几条"。
- **频控友好**：撞上云端限流按批次边界收手、等一会儿再重试，不把剩下的额度一次烧光；云端迟迟不回话改成定期再问。
- 任务身份 = 链接 + 勾选内容 + 目标目录，任一不同即视为新任务，互不串账。

### GB 级 JSON 秒传导入

- 直接吃大体积秒传清单（JSON），**台账按目标目录分账**，模拟与真实两条口径各走各的断点，重跑不重复、不漏。
- **JSON 内部目录浏览**：不用先把大清单拆成小文件，面板 / 机器人里直接展开清单的内部目录树看结构。
- **自主选择秒传**：建任务时勾选清单里的某个内部目录，自动切出一份子清单并入队，只秒你要的那部分。
- **自定义大文件过滤**（默认针对 10GB 一档，可改阈值、可开关）：超大文件跳过，不拖累整趟。
- **每日秒传限额排队**（按额度排队，超限自动进入"超限等待中"，到点续跑）：默认量级约 20 万/日，避免顶穿云端日限。

### 分享链接 → 秒传清单（导出）

反向也行：把一条分享链接的内容读成一份秒传 JSON 清单存下来，导完自动封箱、做完整性校验、三层数字（清单 / 台账 / 云端）互相对账。

### 百万离线下载（直链 / 磁力 → 网盘）

把链接一条条交给云端的「链接任务」，由云端下载并直接落进你指定的那层网盘目录，本机不落地一个字节：

- 一份 txt / csv（一行一条）或手工粘几条都行，超大份按字节游标分批读，不会把内存吃满。
- 「离线下载任务详情」建任务那一刻就长出行，逐条按阶段念（待执行 / 下载中 / 失败重试中 / 失败 / 已完成 / 等待中），可按状态筛、翻页、新加入的排最前。
- 云端判失败的自动按官方那一跳重试（默认 5 次、间隔不小于 10 秒，并发数与重试都在设置的专业模式里可调），「云盘离线下载列表」里还有一颗和官方一样的手动重试。
- 下完的那一层可以一键交给秒传导出，闭环成一份同款 JSON 清单。
- **交出去的链接不会被再交第二遍**（云端不认重复，同名自动加 `(1)`）。




## 功能概览

| 模块 | 可以做什么 |
| --- | --- |
| 秒传导入 | 吃一份 123 云盘的 JSON 秒传清单，按哈希把文件"认领"进你网盘的某一层的目录，不需要先下载再上传。建任务那一刻文件头就读回来了（大小、修改时间、自报条数、编码方式），清单里坏记录与超大文件在这一趟就数得出来 |
| 秒传导出 | 反过来：把你网盘里的一个目录、单个文件、或**别人分享的一条链接**列成一份同款 JSON 清单，供别的工具或另一台机器导入 |
| 链接转存 | 把分享链接里勾选的内容存进你自己的网盘目录。超百万条会被云端拒绝的那一档，面板按目录结构逐层建同名镜像往下存；存不进的逐条进失败台账，腾出空间后在本任务内重试补得回来 |
| 离线下载 | 把直链 / 磁力一条条交给云端的「链接任务」，由云端下载，下完直接出现在你网盘的那一层目录里。本机不落一个字节 |
| 任务与队列 | 上面四样都在这里建任务、排队、启停；一次只跑一条，跑完一条要不要自己领下一条由顶部那颗「自动运行」开关决定（默认关，重启一定是关） |
| 云端目录 | 在面板里翻自己网盘的路径，挑导入目标、导出源、离线落点；挑目录是整页换栏，不是弹窗 |
| 凭证 | 四种登录方式选一：官方登录窗口 / 账号密码登录（不开浏览器，容器与无头机器可用）/ 扫码登录 / 手动导入 `cred.json` |
| Telegram 机器人 | 手机上盯着跑：`/status` `/check` `/queue` `/task` `/log` `/pause` `/stop` `/gate on\|off` `/resume` `/files` `/send` `/dirs` `/notify` `/help`；收到清单、分享链接或直链磁力时，只有在设置页把「自动建任务」拨上且对应落点已选，才会建成一条任务（默认关，落点空着就一条都不建、只回一句）——建好也不代表起跑，机器人自己从不抢跑 |
| 邀请码发放 | 长期VIP可生成签名邀请码发给别人；受邀用户在本机验码后即与长期VIP同权使用全部功能。验码不走网络 |
| 概览与设置 | 导入/导出进度并排看；并发、日限额、大文件阈值、重试与轮询等参数按模块分区摆在设置页 |

## 两种版本

| 形状 | 拿到的是什么 | 怎么起 |
| --- | --- | --- |
| 单文件版（exe） | 一个 `123FastlinkPro-*.exe` | 双击，同样自带运行环境 |

两形共用同一份源码与同一个版本号；关掉面板窗口就等于关掉整个程序（引擎与队列一起收），进度停在最后一个检查点。

## Docker Compose 部署

### 1. 准备目录

把发行包（或仓库）里的 `docker/` 目录放到你想长期留存的位置。台账与凭证都在**命名卷**里，重建镜像不动它：

- `fastlink-data` → `/data`：`panel.json`、`cred.json`、`account.json`、`registry.json`、任务台账、`logs/panel.log`
- `fastlink-manifests` → `/mnt/manifests`：清单目录（界面「📁 浏览…」与导出落盘都停在这里）
- `./input` → `/mnt/input:ro`：待秒传的清单，只读挂载，面板不会写你的源文件

### 2. 创建 `docker-compose.yml`

`docker/` 里已经带好一份，默认只把端口绑在 `127.0.0.1`：

```yaml
services:
  fastlink-panel:
    build:
      context: ..
      dockerfile: Dockerfile
    image: 123pan-fastlink-panel:latest
    ports:
      - "127.0.0.1:8770:8770"
    volumes:
      - fastlink-data:/data
      - fastlink-manifests:/mnt/manifests
      - ./input:/mnt/input:ro
volumes:
  fastlink-data:
  fastlink-manifests:
```

一个 `/data` 卷只能有一个容器在用；两个容器同抢一个卷时彼此看不见。

### 3. 启动与访问

```bash
docker compose up -d --build
docker compose logs -f fastlink-panel      # 首次设置口令在这一行里
```

浏览器打开 `http://localhost:8770`，第一次会摆出一张「首次设置」卡：用户名、密码、再加日志里那一行一次性口令，三格一起填。
之后要改口令，在「设置」页最下面那张「容器访问门」卡里改；改一次会把别处的登录都请出去。
口令忘了：`docker compose exec fastlink-panel rm -f /data/admin.json` 再 `docker compose restart`，日志会给一次新的设置口令，凭证与台账都不受影响。

## 首次配置

| 顺序 | 入口 | 操作与核对 |
| --- | --- | --- |
| 1 | 凭证 | 四种登录方式选一种。登好后「当前凭证」那一行从"尚未验证"变成"已登录：〈账号名〉"，资格校验那张卡跟着变绿 |
| 2 | 任务与队列 | 「新建任务」里选类型、挑两个地址（只能由按钮挑进来，不能手打）、「创建并排队」 |
| 3 | 秒传导入 / 导出 | 先「重新扫描」或「确认源」——这两步只读、一条云端请求都不发 |
| 4 | 第一次跑真的 | **把量收窄**：用「🌳 浏览目录树」切一小段、另存为小清单再建任务；离线下载同理先只放几条。跑完去网盘核对确实多出了这几个文件，再放开整本 |
| 5 | 运行 | 一颗按钮管跑（开始 / 继续 / 重试 / 已完成），暂停与停止是另外两颗 |

## 使用时留意

- **真实秒传、转存与离线下载都不可撤销。** 网盘没有"撤销这一批"，同一批重发一次就多一批副本；离线下载每一次按「开始任务」都在消耗云端配额。落进网盘的东西面板不会替你删。
- **面板起的是 HTTP，别把它当加密用。** Windows 与单文件那两形只听本机、局域网里别人连不上；容器那一形多一道用户名 + 密码的访问门，但登录那一次提交仍是明文 HTTP，跨机器用请在前面架带 TLS 的反向代理，别把端口开到 `0.0.0.0` 了事。
- **凭证只写在本机工作区**，界面上不会出现令牌原文。公共电脑用完请至少点一次「登出」，或直接把工作区文件夹删掉。`panel.json`、`cred.json`、`account.json`、`invite.json` 都含敏感内容，别分享、别提交到任何地方。
- **工作区默认落在程序所在的那个目录**（1.5.12 起）。把程序放进 `Program Files` 这类需要管理员权限的位置，台账与日志会写不进去——那种位置请在「设置」页把工作区指到别处；反过来，删掉程序包就等于把账一起删了。
- **遇到云端压速（风控/限流）不要提高并发。** 面板的做法是原地等一等再重发同一批，等满几轮仍被拒才收手，剩下的逐条进失败台账。
- **「没确认」那一列既不算成功也不算失败**：云端到时间没给结论，去目标目录那一层看一眼，在就别管，确实不在再重发。
- 本程序不提供任何资源；请只对你自己有权限的账号与内容操作。

## 更新与备份

```bash
# 换版本：整包换新，工作区不动
#   常规版 / 单文件版：把旧目录里的数据留着，新包解压到旁边，再在「设置」页把工作区指回老目录
#   容器：docker compose down && docker compose up -d --build   （卷里的账原样接上）

# 备份：拷走整个工作区即可
#   默认工作区 = 程序所在目录；容器那一形是 fastlink-data 这个卷
```

升级前不需要导出任何配置：`registry.json` 与每条任务的台账、断点都在工作区里，新版本读的还是同一批文件。
⚠ 从 1.5.12 之前的版本升级时，工作区默认位置改到了程序旁边，老那份还在 `%LOCALAPPDATA%\123pan-fastlink-gui` ——
在「设置」页把它填回去，账就照旧接得上。

## 项目与使用范围

- 面板只服务 123 云盘，读写走的是官方接口；接口换域名时面板按新域走，旧凭证重新登一次即可落到新域。
- 往外发东西只有三处，且都由你开关：① 123 云盘自己的读写（本职）；② 你亲手开启的 Telegram 机器人；③ 你主动使用的那一台邀请码发放服务。除这三处之外，一个字都不出这台机器。
- 本软件由 AI 辅助编写，请合理、合规、合法使用，不要用它传播侵权内容。使用它造成的容量占用、重复文件、账号风控等后果由使用者自行承担。
- 逐版本的改动见 `升级说明.md`；完整用法、常见问题与字段口径见发行包里的 `app/README.md`。
